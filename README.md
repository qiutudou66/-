# 数码宝贝 · 二手手机店管理小程序

给二手手机店用的进销存 + 管账小程序：收机入库 → 卖机出库 → 客户退货重新入库 → 再卖，收支流水自动记账，看板看当天/当月利润。

> 小程序名「数码宝贝」；首页横幅显示的「店头」是每个老板注册时填的**店铺名称**（默认「来财」，可改）。

- **前端**: 微信小程序原生 (WXML/WXSS/JS)
- **后端**: 微信云开发（云函数 + 云数据库 + 云存储）
- **数据库**: 云数据库（文档型）

## 核心概念

### 手机（phone 集合，一机一条）
每台手机是**唯一库存**，按 **IMEI** 区分，不是按数量。

状态流转：

```
0 在库 ──卖机──▶ 1 已售 ──退货入库──▶ 2 退货入库(可再卖) ──再卖──▶ 1 已售
```

字段：品牌 / 型号 / 容量 / 电池寿命 / 颜色 / 成色 / IMEI / 成本价 / 期望售价 / 成交价 / 回收日期 / 售出日期 / 状态 / 详情 / 图片 / 回收人信息 / 备注

### 流水（flow 集合）
每笔钱的进出都记一条流水，带正负号：**正 = 你收钱，负 = 你掏钱**。

| 类型 | 金额 | 什么时候记 |
|---|---|---|
| 1 收机 | `-成本` | 收手机入库 |
| 2 卖机 | `+成交价` | 卖出 |
| 3 退货入库 | `-退款金额` | 买家退货重新入库（默认退全额成交价，可改） |

## 财务口径（对账用）

> **一句话：利润 = 已实现销售毛利，只算卖出去的。收机只是支出，不是亏损。**

在库没卖的机子，利润是 **0**——收机花了钱，那是货压在手里（资产），不是亏了。卖出去一台，这台才产生利润 = 卖价 - 成本。

一台 iPhone 12（成本 2000）走完整流程：

| 阶段 | 状态 | 利润 |
|---|---|---|
| 收机 | 在库 | 0（不赚不亏） |
| 卖出 2500 | 已售 | +500 |
| 客户退货（退 2500） | 退货在库 | 0（卖出利润撤销） |
| 再卖 2600 | 已售 | +600 |

这台机最终利润 = **600** = 最终卖价 - 成本。

**收入/支出是另一回事**（现金流，按流水类型分）：

| 类型 | 归到 |
|---|---|
| 卖机 | 收入 |
| **退货入库** | **冲减收入**（营收里减掉） |
| 收机 | 支出 |

> **「收入 - 支出」≠「利润」。** 收入/支出看流水（进账多少、花出去多少），利润只看卖出去赚了多少。在库手机多时，支出大、利润却是 0，这是对的——货压在手里还没变现。

**对账勾稽（验收方法）**：
1. 台数：`在库 + 已售 + 退货入库 = 总入库台数`
2. 利润 = 所有 `status=1` 手机 `(sell_price - cost_price)` 之和（按卖出日期归属区间）

## 账号与多店

- **登录注册一体**：登录页填账号/密码 + 店铺名称/昵称，账号存在就直接登录，不存在就自动注册成老板开店（store_id = 老板自己的 id）；注册时填**店铺名称**（默认「来财」），就是首页横幅显示的名字
- **员工账号**：老板在「我的」里手动添加员工账号（账号/密码/姓名），员工继承老板的店铺名
- **分店隔离**：每个账号、每台手机、每笔流水都带 `store_id`，各店只能看自己店的数据，互不可见
- **权限**：员工与老板都能收机/卖机/退货入库；**「删除入库」仅老板可操作**（员工端按钮隐藏 + 云端校验）
- **默认账号**：admin / 123456（自动创建为老板，归属 admin 自己的一家店）

## 云函数

| 云函数 | 职责 |
|---|---|
| `user` | 登录注册一体 / 添加·列表·移除员工 / 首次自动初始化 admin |
| `phone` | 收机/列表/详情/修改/卖机/退货入库/删除入库（全部按 store_id 隔离） |
| `flow` | 流水列表 / 收支统计 / 首页看板（全部按 store_id 隔离） |
| `ocr` | 拍照识别贴纸文字（百度 OCR），返回 IMEI/型号/容量/品牌/电池寿命/充电次数 |

集合 `users` / `phones` / `flows` 由云函数**首次调用时自动创建**，无需手动建。

## 快速开始

1. 微信开发者工具 → 导入项目，选择本目录，填入你的 **AppID**
2. 点「云开发」开通，创建环境，把**环境 ID** 填到 `app.js` 的 `cloudEnv`
3. 分别右键 `cloudfunctions/user`、`phone`、`flow`、`ocr` → 「上传并部署：云端安装依赖」
4. 「拍照识别贴纸」需在云开发控制台给 `ocr` 云函数配环境变量 `BAIDU_API_KEY` / `BAIDU_SECRET_KEY`（百度智能云免费申请），不配则按钮提示未配置
5. 点「编译」，登录 `admin / 123456`（自动建管理员并迁移老数据，无需手动初始化、无需建集合、无需构建 npm）

> 坑：开发者工具若开了代理（Clash 等）且代理没运行，上传会报 `ECONNREFUSED 127.0.0.1:7892`，关掉代理或启动代理软件即可。

## 技术要点

- **卖机并发防重**：云函数事务内读手机状态，仅 `在库(0)/退货(2)` 可卖，状态非可售直接拒绝，不会一台机卖两次。
- **金额口径**：流水统一带符号存储（收入正、支出负），利润 = SUM。
- **多店隔离**：所有 phone/flow 查询都带 `store_id` 过滤；事务内再校验手机归属，杜绝跨店读写。
- **身份传递**：`utils/cloud.js` 每次调用云函数自动附带 `_userId/_role/_store_id`，登录态存本地。
- **登录**：密码由云函数 sha256 加密存储，小程序端无任何 npm 依赖。
